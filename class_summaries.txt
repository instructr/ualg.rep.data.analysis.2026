#------------------ Class 1 (max 3000 chars) ------------------#

Learning Objectives

By the end of this session, students should be able to:

- Define reproducibility in the context of data analysis
- State the three rules of tidy data
- Identify common violations of tidy data principles
- Transform untidy data into tidy format

Content Covered

1. Introduction to Reproducibility

Reproducibility means that given the same data and code, another person (or the original analyst at a later time) can obtain exactly the same results. This requires organized data, code-based analysis, documentation, and accessible files.

The session used the Reinhart-Rogoff case (2010/2013) to illustrate how opaque analytical workflows can lead to consequential errors that go undetected.


2. Tidy Data Principles

Based on Wickham (2014), tidy data follows three rules:
- Each variable forms a column
- Each observation forms a row
- Each type of observational unit forms a table

Common violations include: column headers that are values rather than variable names; multiple variables stored in a single column; variables stored in both rows and columns; and observational units spread across multiple tables without clear linkage.

Tidy data enables direct use of analytical tools without error-prone reformatting steps.


3. Practical Activity: Dice Exercise

Students worked in small groups to generate, record, and tidy a dataset by hand using dice rolls. The activity had four phases: designing a recording sheet, collecting data, restructuring the data into tidy format, and producing a hand-drawn visualization. The exercise demonstrated how implicit recording conventions can produce untidy data and highlighted the importance of deliberate data organization from the point of collection.



#------------------ Class 2 (max 3000 chars) ------------------#

--- Learning Objectives ---

By the end of this session, students should be able to:

- Explain why programming is essential for reproducible data analysis and justify the choice of R
- Navigate the RStudio IDE and configure a project for reproducible work
- Assess their own R proficiency and select the appropriate learning pathway

Depending on the pathway followed:

- Beginners: learn R interactively via `swirl`, covering vectors, sequences, missing values, subsetting, matrices, data frames, logic, and base graphics.

- Intermediate: load and inspect a biology dataset, compute descriptive statistics, produce visualisations with ggplot2, and conduct a two-sample t-test.

- Advanced: clean a messy dataset, perform exploratory analysis and PCA, and build and evaluate a machine learning classifier with tidymodels.

--- Content Covered ---

1. Why R and Why Program

The session opened with a discussion on why scripted, code-based workflows are preferable to manual or spreadsheet-based approaches, and why R was chosen over alternatives such as Python and Julia, highlighting its statistical ecosystem, reproducibility support, and active development community for biomedical and biology sciences.

2. The RStudio Environment

Students were introduced to the four panes of the RStudio IDE (source editor, console, environment/history, and files/plots/packages/help) and to project creation. 

3. Differentiated Practical Tutorials

Students followed one of three self-paced tutorials according to their prior experience with R.

- Beginners used the `swirl` package to learn R interactively from within the R console, covering basic building blocks, sequences, vectors, missing values, subsetting, matrices and data frames, logic, and base graphics.

- Intermediate students analysed a mice weight dataset to explore the effect of a high-fat diet on body weight, covering experimental design discussion, data loading and inspection, descriptive statistics, ggplot2 visualisations, Pearson correlation, linear modelling, and a two-sample t-test with group discussion on results interpretation.

- Advanced students completed a mini-project taking a messy version of the Palmer Penguins dataset from raw input to a trained classifier, comprising seven stages: project setup; data loading with explicit parsing; cleaning with janitor and tidyverse to resolve capitalisation inconsistencies, mixed missing value formats, and incorrect column types; grouped descriptive statistics and correlation analysis; visualisation with histograms, boxplots, pairs plots, and a correlation heatmap; PCA with scree plot and biplot; and random forest classification with tidymodels, evaluated using accuracy, a confusion matrix, and 5-fold cross-validation. The tutorial closed with a demonstration of classifying new observations and a set of extension exercises.




#------------------ Class 3 (max 3000 chars) ------------------#

Learning Objectives

By the end of this session, students should be able to:

- Assess their current R programming proficiency across core tasks
- Install and configure R, RStudio, and Git on a personal computer
- Create and secure a GitHub account using SSH key authentication
- Create an R Project with version control initialised locally
- Design a principled directory structure for a data analysis project
- Connect a local Git repository to a remote GitHub repository and perform an initial commit and push

Content Covered

1. R Proficiency Calibration

Students worked through a set of hands-on prompts in RStudio covering the construction and manipulation of vectors, exploration of built-in datasets, subsetting with logical conditions, writing functions that return named lists, grouped summaries using base R or dplyr, and data visualisation with base R or ggplot2. The exercise was framed as a calibration rather than an assessment, with group discussion used to surface different approaches and establish a shared vocabulary for the remainder of the course.

2. Toolchain Installation

R was installed from CRAN and RStudio Desktop from the Posit website. Platform-specific considerations were addressed for Windows and macOS, including the choice of the `arm64` build for Apple Silicon machines. Git was installed and configured with a global user identity, establishing the name and email that will be recorded in every subsequent commit.

3. GitHub Account and SSH Authentication

Students created a GitHub account and generated an `ed25519` SSH key pair. The public key was registered on GitHub, enabling passwordless authentication between the local machine and the remote repository. The connection was verified with `ssh -T git@github.com`.

4. Project Creation and Directory Structure

Students created a new R Project in RStudio with Git initialised locally, then structured it according to a principled directory layout separating raw data, processed data, R scripts, outputs, figures, and documentation. The rationale for separating raw from processed data and for excluding large or sensitive files via `.gitignore` was discussed in the context of reproducibility.

5. Connecting to GitHub and First Push

An empty repository was created on GitHub and linked to the local project using `git remote add origin` followed by `git push -u origin main`. Students staged their initial files, wrote a commit message, and pushed to GitHub, confirming the workflow through the RStudio Git pane and the GitHub web interface.


#------------------ Class 4 (max 3000 chars) ------------------#

Learning Objectives

By the end of this session, students should be able to:

- Present a dataset and identify its observational unit, response variables, explanatory variables, and any nesting or repeated-measures structure
- Navigate the Nature Scientific Data journal and extract documentation patterns from a data descriptor paper
- Map an experimental design onto a tidy table layout before writing any code
- Import raw data into R, inspect its structure, and apply tidyverse transformations to reshape it toward tidy format

Content Covered

1. Dataset Presentations and Variable Identification

Each student presented their dataset to the group, describing its origin and research question. For each dataset, the class collectively identified the observational unit, response and explanatory variables, and any hierarchical or repeated-measures structure. The exercise reinforced that the shape of a tidy table is determined by the experimental design, not by convenience.

2. Browsing Nature Scientific Data

Students searched the Nature Scientific Data journal and selected one data descriptor paper relevant to their field. The reading focused on how professional publications document variables, metadata, provenance, units, and missing-value conventions: extracting a transferable pattern for sufficient dataset documentation.

3. Group Discussion: From Professional Standards to Own Practice

Students identified which elements from the data descriptor were absent from their own project documentation and defined concrete actions such as adding a variable dictionary or documenting the meaning of missing values.

4. From Experimental Design to Tidy Format

Students sketched their target tidy table on paper: column names, expected types, and example rows. Common structural issues were reviewed, including values embedded in column names requiring pivoting, compound columns requiring separation, and inconsistent categorical coding requiring standardisation with explicit factor level ordering.

5. Hands-on: Import, Inspect, and Tidy

Students created an R script in `scripts/` to read, inspect, and begin tidying their data. Inspection covered dimensions, column types, and missingness checked against the sketch. Tidying operations included pivoting, column separation, and factor ordering as appropriate. Processed data was saved to `data/processed/`, maintaining the chain from raw data through tidying script to analysis-ready output.

6. Commit, Push, and Wrap-up

Students committed their work with descriptive messages and pushed to GitHub. The session concluded with a review of the deliberate sequence: presenting data, learning from professional descriptions, sketching a tidy structure, then implementing it, and an introduction to the next class on data exploration and visualisation.

#------------------ Class 5 (max 3000 chars) ------------------#

Learning Objectives
By the end of this session, students should be able to:
- Verify that a tidy dataset is complete, correctly typed, and consistent with the experimental design
- Compute overall and grouped summary statistics for continuous and categorical variables using tidyverse
- Select and produce appropriate exploratory visualisations based on data structure and research question
- Interpret exploratory outputs critically: identifying plausible ranges, group balance, distributional shape, and potential outliers

Content Covered

1. Individual Progress Check
Each student pulled the latest state of their project, ran their tidying script from top to bottom in a fresh R session, and confirmed the processed file was present in `data/processed/`. The checkpoint required every student to load their tidy data and display it with `glimpse()` before proceeding.

2. Individual Tidy Data Review
Students showed their tidy dataset to the instructor. Each dataset was reviewed against five criteria: one variable per column, one observation per row, appropriate column types, documented missing values, and a row count consistent with the experimental design. Remaining issues with factor levels or column types were corrected at this stage.

3. Summary Statistics
Students created an EDA script (`scripts/02_eda.R`) and loaded their tidy data. Overall summaries were computed with `summary()` and a structured `summarise(across())` call covering count, mean, standard deviation, median, minimum, and maximum for all numeric variables. Grouped summaries disaggregated these statistics by the main grouping variable, with explicit attention to sample sizes per group. For datasets with categorical outcomes, counts and proportions were computed with `count()` and `mutate()`.

4. Exploratory Visualisation
Students selected and produced visualisations matched to their data structure. Covered plot types included: histograms and density plots for distributional shape of continuous variables; box plots with jittered points and violin plots for group comparisons; scatter plots with linear trend lines for relationships between continuous variables; and line plots with standard error ribbons for time series or ordered structures. Each plot type was motivated by the question it answers, and students were asked to annotate each plot in their script with a one-sentence statement of what they were looking for and what they found.

5. Commit, Push, and Wrap-up
Students committed their EDA script with a descriptive message and pushed to GitHub.
